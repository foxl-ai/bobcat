\begin{abstract}
Bobcat is a typed-decision model. A request carries a state (text or JSON) and one or more
questions whose answer space the caller defines at request time: a \emph{Choice} among
named candidates, a \emph{Noul} (the probability that a statement is true) or a
\emph{Score} on an ordinal rubric. Bobcat never generates text for a decision. For each
question it reads the logits of the offered single-token candidate identifiers at the first
answer position of a language model, and the host builds a closed JSON reply from the
caller's own names; a separate validator rejects any reply outside that contract. The
model is Qwen3.8-27B (a hybrid of Gated DeltaNet and full-attention layers) with a rank-16
LoRA adapter trained for one epoch on 50,938 labelled decisions, followed by scalar
temperature calibration. On a sealed evaluation of six product tasks built from native
Korean sources (1,607 decisions, evaluated once after freezing a release manifest),
task-macro accuracy is 94.6\% against 84.5\% for the same-input zero-shot base model
(+10.2 points, paired component-bootstrap 95\% interval [+7.7, +12.3]). The tool-call
review task, never trained on, reaches 99.0\% against 79.2\% on 96 decisions drawn from only
three situations. Across 12,846 HTTP requests to two models, including 2,304
output-contract attacks per model, we observed no contract violation, and repeated requests
returned bit-identical numbers. A REINFORCE objective with a proper-score reward, whose expected gradient equals that of
the half Brier score, matched direct Brier training without exceeding it in two experiments;
correctness-only reward worsened calibration. On the 20 workflow examples that TypeSafe
published for its Jev model, Bobcat agrees with TypeSafe's reference consensus on 91.8\% of
329 questions against 90.9\% for Jev's published answers (workflow-mean difference $-0.2$
points [$-3.8$, $+4.8$]) and places more probability on the reference answer (0.889 against
0.850), but is 3 to 19 times slower per case on its current single-L40S deployment. The main
negative result is semantic: when a sentence in the state names a wrong answer, the model
switches to that answer in 39.4\% of eligible cases after training, against 21.0\% before
training. On one B300 GPU a 512-token, 8-candidate request takes 97\,ms at the median, and
50\,ms on one H100 with vLLM and FP8 weights; batched throughput is about 16k input tokens
per second on either GPU. The designated reference model has not yet been run on the same
evaluation, so the release gates that compare against it are not judged. Bobcat is
wire-compatible with TypeSafe's System One SDK; its LoRA adapter and code are released under
Apache-2.0 (Section~\ref{sec:availability}).
\end{abstract}
